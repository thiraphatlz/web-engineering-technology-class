3.1 ตัวเชื่อมฐานข้อมูล

สร้าง instance เดียวแล้ว export ให้ทุกไฟล์ใช้ร่วมกัน ไม่สร้างใหม่ทุก request

3.2 ตั้งค่า multer

อธิบาย
  • ใน ES module ไม่มีตัวแปร __dirname จึงหาโฟลเดอร์ของไฟล์จาก import.meta.url แล้วชี้ไปที่ api/uploads
  • ชื่อไฟล์: สุ่มด้วย randomUUID() ไม่เอาชื่อเดิมของผู้ใช้ เพราะอาจซ้ำกัน หรือแอบใส่ ../ เพื่อเขียนทับไฟล์อื่น
  • fileFilter: รับเฉพาะรูป ถ้าส่งไฟล์อื่นมาจะโยน error
  • limits: จำกัด 5MB กันคนยิงไฟล์ใหญ่มาให้ดิสก์เต็ม

3.3 ตัวช่วยเล็กๆ

อธิบาย
  • removeFile รับ path อย่าง /files/abc.jpg แล้วลบไฟล์จริงบนดิสก์ ใช้ตอนแก้รูป ลบสินค้า หรือ request ล้มเหลว
  • ah (async handler) ห่อ controller ให้ error ใดๆ ถูกส่งต่อไปยัง error handler กลางใน app.js โดยอัตโนมัติ
  • bad('...') สร้าง error ที่มี status: 400 เอาไว้ throw เวลาข้อมูลที่ส่งมาไม่ครบ

Controller: ตรรกะ CRUD

Controller คือฟังก์ชันที่รับ request แล้วตอบ response แต่ละตารางมี 5 ฟังก์ชัน: list, get, create, update, remove

4.1 Category (ไม่มีไฟล์ ใช้ JSON)

อธิบาย
  • req.params.id คือค่าจาก URL /api/categories/5 เป็น string จึงใช้ + แปลงเป็นเลข
  • req.body คือข้อมูลที่ส่งมาใน body ของ request
  • findUniqueOrThrow, update และ delete ของ Prisma จะ throw error รหัส P2025 ถ้าไม่พบข้อมูล เราแปลงเป็น 404 ที่เดียวใน app.js
  • create ตอบ 201 (Created) ส่วน remove ตอบ 204 (สำเร็จ ไม่มีเนื้อหา)
  • จุดสำคัญของ remove: Cascade ลบแถวสินค้าใน DB แต่ ไม่ลบไฟล์รูปบนดิสก์ เราจึงดึงรายการสินค้ามาก่อนแล้วลบไฟล์ทีหลัง ถ้าไม่ทำ ไฟล์ขยะจะค้างใน uploads/

4.2 Product (มีไฟล์ ใช้ multipart)

อธิบาย
  • เมื่อ route ผ่าน multer มาแล้ว ไฟล์อยู่ที่ req.file และฟิลด์ข้อความอยู่ที่ req.body (ค่าทุกตัวเป็น string จึงต้อง +price)
  • req.file.filename คือชื่อที่สุ่มไว้ใน upload.js เราเก็บ /files/ชื่อนั้น ลงคอลัมน์ imageUrl
  • ...(name && { name }) เป็นลูกเล่นของ JS: ถ้าไม่ส่ง name มา จะไม่แก้ฟิลด์นั้น
  • ลำดับใน update: อัปเดต DB ให้สำเร็จก่อน แล้วค่อยลบรูปเก่า ถ้า DB พัง รูปเก่ายังอยู่ ไม่เสียหาย
  • ถ้า create ล้มเหลว (ข้อมูลไม่ครบ) ไฟล์ที่เพิ่งอัปโหลดจะถูกลบโดย error handler ใน app.js ไม่ต้องจัดการเองในแต่ละ controller

Route: จับคู่ URL กับ Controller

อธิบาย
  • รูปแบบ REST: ใช้ HTTP method บอกว่าทำอะไร และ URL บอกว่ากับอะไร: GET อ่าน, POST สร้าง, PUT แก้, DELETE ลบ
  • :id คือพารามิเตอร์ใน URL ที่จะไปอยู่ใน req.params.id
  • upload.single('image') คือ middleware ที่ทำงาน ก่อน controller: รับไฟล์จากฟิลด์ชื่อ image เก็บลงดิสก์ แล้วส่งต่อให้ controller
  • Category ไม่มีไฟล์จึงไม่ต้องใช้ multer

app.js: ประกอบทุกอย่างเข้าด้วยกัน

อธิบาย
  • cors() เบราว์เซอร์ห้ามหน้าเว็บที่พอร์ต 3001 เรียก API พอร์ต 3000 โดยค่าเริ่มต้น บรรทัดนี้อนุญาต ถ้าลืมจะเห็น CORS error ในคอนโซล
  • express.json() และ urlencoded อ่าน body แบบ JSON และแบบฟอร์มธรรมดา ส่วน multipart multer จัดการเอง
  • express.static ทำให้ไฟล์ใน uploads/ เปิดผ่าน URL /files/ชื่อไฟล์ ได้ โดยไม่ต้องเขียน controller เสิร์ฟไฟล์เอง
  • Error handler ต้องวางท้ายสุด และต้องมี 4 พารามิเตอร์ (err, req, res, next) Express ถึงจะรู้ว่าเป็นตัวจัดการ error ตรงนี้แปลงรหัสของ Prisma/multer เป็นข้อความไทยพร้อมสถานะที่ถูกต้อง

  • NEXT_PUBLIC_API_URL ตอน deploy จริงตั้งค่านี้เป็น URL ของ Express ไม่ต้องแก้โค้ด (ตัวแปรที่ขึ้นต้น NEXT_PUBLIC_ เบราว์เซอร์อ่านได้)
  • img(url) แปลง /files/abc.jpg เป็น URL เต็มของ Express เพราะรูปอยู่บนเซิร์ฟเวอร์ API ไม่ใช่ Next
  • ส่ง JSON: ต้องบอก Content-Type: application/json
  • ส่ง FormData: ห้ามตั้ง Content-Type เอง เบราว์เซอร์ต้องใส่ boundary ที่ใช้คั่นไฟล์ให้เอง ถ้าตั้งเองจะทำให้ req.body ว่าง
  • ถ้า response ไม่ ok ให้ throw ข้อความจากเซิร์ฟเวอร์ ฝั่งหน้าเว็บจับด้วย try/catch แล้วแสดงให้ผู้ใช้เห็น

หน้าหมวดหมู่ (CRUD แบบไม่มีไฟล์)

อธิบาย
  • 'use client' บรรทัดแรกบอกว่าไฟล์นี้ทำงานในเบราว์เซอร์ (ใช้ state, event ได้) ถ้าไม่ใส่ Next จะถือเป็น server component ซึ่งใช้ useState ไม่ได้
  • useState เก็บข้อมูลและ error, useEffect เรียก load() ตอนเปิดหน้า, useCallback ทำให้ load เป็นฟังก์ชันตัวเดิมตลอด จึงไม่วนลูป
  • run() เป็นตัวห่อ: ทำคำสั่ง → ถ้าสำเร็จโหลดรายการใหม่ → ถ้าพังแสดงข้อความ error เขียน try/catch ที่เดียวใช้ได้ทั้ง เพิ่ม แก้ ลบ
  • แต่ละปุ่มตรงกับ method ของ API: เพิ่ม = POST, แก้ไข = PUT, ลบ = DELETE
  • prompt และ confirm ของเบราว์เซอร์ใช้ง่ายสำหรับตัวอย่าง ของจริงควรทำช่องกรอกในหน้าเอง

อธิบาย
  • new FormData(form) รวบทุกช่องในฟอร์มที่มี name (ข้อความ, ตัวเลข, select และไฟล์) เป็นก้อนเดียว ชื่อ image ต้องตรงกับ upload.single('image') ฝั่ง Express

  • พรีวิวรูป: URL.createObjectURL(file) สร้าง URL ชั่วคราวให้ดูรูปได้ทันทีก่อนอัปโหลด
  • defaultValue เติมค่าเดิมในโหมดแก้ไข, busy ปิดปุ่มระหว่างส่ง กันกดซ้ำ
  • accept="image/..." กรองไฟล์ที่ฝั่งผู้ใช้ แต่ ไม่ใช่ความปลอดภัย ใครก็ข้ามได้ การตรวจจริงอยู่ที่ fileFilter ฝั่ง Express

อธิบาย

Swagger (OpenAPI) และ Postman

OpenAPI คือไฟล์ .yaml ที่บรรยาย API ว่ามี endpoint อะไร รับอะไร ตอบอะไร ส่วน Swagger UI คือหน้าเว็บที่อ่านไฟล์นั้นแล้วให้เรากด "Try it out" ยิง API ได้เลย และ Postman import ไฟล์เดียวกันเป็น collection พร้อมทดสอบได้ทันที ไฟล์เดียวจึงใช้ได้ทั้งเป็นเอกสาร, เครื่องมือทดสอบ และ (ถ้าต้องการ) ตัวตรวจ request

13.1 เขียน openapi.yaml

สร้างไฟล์ api/openapi.yaml (อยู่ข้าง package.json ไม่ใช่ใน src/) ไฟล์นี้บรรยาย API ที่เราสร้างในขั้น B4-B6 ครบทุก endpoint

อธิบาย
  • paths คือรายการ endpoint: ใต้แต่ละ URL ระบุ method (get/post/put/delete) แล้วบอก summary, ข้อมูลที่รับ (requestBody, parameters) และสิ่งที่ตอบ (responses แยกตามรหัสสถานะ)
  • {id} ใน URL คือ path parameter ประกาศครั้งเดียวไว้ใน components/parameters/Id แล้วอ้างด้วย $ref ทุกที่ที่ใช้
  • $ref คือการอ้างถึงของที่นิยามไว้ใน components (schema, response, parameter) เพื่อไม่ต้องเขียนซ้ำ ถ้าแก้ที่เดียว ทุกที่ที่อ้างก็เปลี่ยนตาม
  • หมวดหมู่ใช้ JSON, สินค้าใช้ multipart/form-data ตรงกับที่ Express รับจริง (หมวดหมู่ผ่าน express.json(), สินค้าผ่าน multer)
  • ฟิลด์รูปประกาศเป็น type: string + format: binary นี่คือวิธีบอก OpenAPI ว่า "นี่คือไฟล์" Swagger UI จะแสดงปุ่มเลือกไฟล์ให้เอง
  • operationId เป็นชื่อเฉพาะของแต่ละ operation เครื่องมือสร้างโค้ดใช้เป็นชื่อฟังก์ชัน ควรตั้งให้ไม่ซ้ำกัน
  • allOf คือ "รวมหลาย schema" เช่น ProductWithCategory = Product + ฟิลด์ category ตรงกับ include: { category: true } ใน controller
  • nullable: true ที่ imageUrl เพราะสินค้าที่ไม่มีรูปจะได้ null
YAML ไวต่อการย่อหน้า ใช้ space เท่านั้น (ห้ามใช้ Tab) และต้องย่อหน้าตรงกัน ถ้าย่อหน้าผิดแม้บรรทัดเดียว จะเห็น error แบบ YAMLParseError ตอนเริ่มเซิร์ฟเวอร์ ใช้ editor.swagger.io วางไฟล์เพื่อตรวจ จะชี้บรรทัดที่ผิดให้

13.2 เปิดหน้า Swagger UI ที่ /docs

ถ้าคุณทำตามส่วน A สคริปต์ใส่ส่วนนี้ใน app.js ให้แล้ว ข้ามไปทดสอบที่ /docs ได้เลย ส่วนด้านล่างสำหรับคนที่สร้างไฟล์เองตามส่วน B

เพิ่มใน api/src/app.js โดยวาง import ไว้บนสุดคู่กับ import เดิม และวาง app.use ไว้ก่อนบรรทัด app.use('/api/categories', ...):

อธิบาย
  • swagger-ui-express เสิร์ฟหน้า Swagger UI ให้ที่ /docs โดยอ่านสเปกที่เราส่งให้
  • yaml แปลงไฟล์ .yaml เป็นอ็อบเจ็กต์ JS ที่ Swagger UI ต้องการ
  • เพราะ /docs อยู่ใน Express ตัวเดียวกับ API จึงไม่มีปัญหา CORS ตอนกด "Try it out"

รีสตาร์ท npm run dev แล้วเปิด http://localhost:3000/docs ลองทดสอบตามลำดับนี้:

  1. POST /api/categories → กด Try it out ใส่ {"name":"Food"} → Execute ควรได้ 201
  2. POST /api/products → กรอก name, price, categoryId แล้วกด Choose File เลือกรูป → Execute
  3. GET /api/products → ต้องเห็นสินค้าพร้อม imageUrl
  4. DELETE /api/categories/1 → ได้ 204 และไฟล์รูปใน uploads/ หายไป

13.3 นำสเปกเข้า Postman

ได้ collection ครบทุก endpoint โดยไม่ต้องสร้าง request เอง มี 3 วิธี:

  1. นำเข้าไฟล์: Postman → Import → ลาก openapi.yaml ใส่ ระบบจะสร้าง collection โดยจัดโฟลเดอร์ตาม tag (Categories, Products)
  2. นำเข้าผ่านลิงก์: Import → วาง http://localhost:3000/openapi.json (ใช้ได้กับโปรแกรม Postman บนเครื่อง ส่วน Postman เวอร์ชันเว็บเข้าถึง localhost ไม่ได้)
  3. แปลงด้วยคำสั่ง (เหมาะกับสคริปต์หรือ CI): แล้ว Import ไฟล์ collection.json เข้า Postman อีกที

ใน Postman ตัว request ของ POST /api/products จะเป็นแบบ form-data ให้เปลี่ยนชนิดช่อง image เป็น File แล้วเลือกรูป

13.4 เมื่ออาจารย์ให้ไฟล์ Swagger มา (ทำ backend จากสเปก)

ถ้าสเปกมาก่อนโค้ด ให้ทำตามลำดับนี้:

  1. ตรวจเวอร์ชัน: เปิดไฟล์ดูบรรทัดแรก ถ้าเป็น swagger: "2.0" (ของเก่า) ให้แปลงเป็น OpenAPI 3 ก่อน เพราะเครื่องมือส่วนใหญ่ในปัจจุบันเน้น 3.x
  2. ดูสเปกใน Swagger UI ด้วยขั้น B13.2 และ import เข้า Postman ด้วยขั้น B13.3 เพื่อเห็นภาพรวมว่ามี endpoint อะไร
  3. เขียนตารางใน schema.prisma ให้ตรงกับ schema ในสเปก (ชื่อฟิลด์ ชนิดข้อมูล ความสัมพันธ์) แล้วทำขั้น B2-B6 ตามเดิม โดยให้ URL, ชื่อฟิลด์ และรหัสสถานะตรงกับสเปกทุกตัว
  4. ทดสอบกลับ: ยิงด้วย collection ที่ import จากสเปก ถ้ายิงแล้วผลไม่ตรงกับที่สเปกบอก แปลว่า backend ยังไม่ตรงสเปก

ถ้าจะ deploy ระบบนี้จริง

ข้อจำกัดสำคัญ: ระบบในบทเรียนเก็บรูปในโฟลเดอร์ uploads/ และข้อมูลในไฟล์ SQLite ซึ่งใช้ไม่ได้บน Vercel เพราะดิสก์ของ Vercel เขียนได้ชั่วคราวและหายทุกครั้งที่ deploy หรือเมื่อฟังก์ชันถูกสร้างใหม่

  • ฝั่ง Express ควรไปรันบนที่ที่มีเซิร์ฟเวอร์ถาวรและดิสก์ที่ไม่หาย เช่น Railway, Render หรือ VPS พร้อมต่อ volume เก็บ uploads/ และ dev.db
  • ทางเลือกที่ขึ้น Vercel ได้ทั้งหมด: เปลี่ยนฐานข้อมูลเป็น Postgres ที่โฮสต์ภายนอก (provider = "postgresql") และเปลี่ยนที่เก็บรูปเป็น object storage เช่น Vercel Blob หรือ S3 ซึ่งต้องแก้ upload.js และ removeFile

C. บทเรียน Express

เรียน Express ตั้งแต่ติดตั้งจนเขียน API ได้เอง ทุกตัวอย่างเป็นไฟล์เต็มที่คัดลอกไปรันได้ และผมรันทดสอบทุกไฟล์แล้ว (Node 24, Express 4) ใช้ Node 20 ขึ้นไป

Express คืออะไร

Express คือไลบรารีของ Node.js สำหรับสร้างเว็บเซิร์ฟเวอร์และ API มันรับ request จากผู้ใช้ ส่งผ่านขั้นตอนต่างๆ ตามลำดับ แล้วตอบ response กลับไป

  1. Request เบราว์เซอร์หรือแอปส่งมา เช่น POST /todos
  2. Middleware ด่านตรวจเรียงกัน เช่น อ่าน JSON, ตรวจล็อกอิน, บันทึก log
  3. Route ฟังก์ชันที่ตรงกับ method และ URL นั้น ทำงานจริงแล้วตอบ
  4. Response / Error ส่ง JSON กลับ หรือถ้ามี error ไปที่ตัวจัดการ error

ทุกอย่างใน Express คือ ฟังก์ชันที่รับ (req, res, next) เข้าใจ 3 ตัวนี้ก็เข้าใจ Express เกือบทั้งหมด:

ตัวแปรคืออะไรตัวอย่างที่ใช้
reqข้อมูลที่ผู้ใช้ส่งมาreq.params, req.query, req.body, req.get('header')
resตัวช่วยตอบกลับres.json(), res.status(), res.send(), res.redirect()
nextส่งต่อให้ฟังก์ชันถัดไป (ถ้าส่ง error เข้าไปจะข้ามไปตัวจัดการ error)next(), next(err)

ติดตั้งและโปรแกรมแรก

ต้องมี Node.js 20 ขึ้นไป (เช็กด้วย node -v) จากนั้นเปิด PowerShell:

อธิบาย
  • npm init -y สร้าง package.json (ทะเบียนบอกว่าโปรเจกต์ใช้ไลบรารีอะไร)
  • type=module ให้เขียน import แบบใหม่ได้ ถ้าไม่ตั้ง ต้องใช้ require() แบบเก่า
  • node --watch รีสตาร์ทเองเมื่อบันทึกไฟล์ จึงไม่ต้องกด Ctrl+C แล้วรันใหม่ทุกครั้ง
  • express@4 ล็อกเวอร์ชัน 4 ไว้ ถ้าพิมพ์ npm i express เฉยๆ จะได้เวอร์ชัน 5 ซึ่งต่างกันบางจุด (ดูหัวข้อ C11)

สร้างไฟล์ hello.js แล้วรัน npm run dev:

อธิบาย
  • express() สร้างแอป เก็บไว้ในตัวแปร app
  • app.get('/', handler) บอกว่า "ถ้ามีคนเรียก GET ที่ / ให้รัน handler นี้"
  • res.send() ตอบกลับเป็นข้อความ
  • app.listen(PORT) เปิดรับ request ที่พอร์ตนั้น process.env.PORT || 3000 แปลว่า "ใช้พอร์ตที่ระบบกำหนด ถ้าไม่มีให้ใช้ 3000" ตอน deploy จริงผู้ให้บริการมักกำหนดพอร์ตมาให้
ลองดู: เปิด http://localhost:3000 ต้องเห็นข้อความ Hello Express ถ้าเห็น EADDRINUSE แปลว่าพอร์ต 3000 ถูกใช้อยู่ ปิดโปรแกรมนั้นก่อนหรือรันด้วย $env:PORT=3001; npm run dev

Route และ Response

Route คือการจับคู่ HTTP method + URL กับฟังก์ชัน ตัวอย่างนี้รวมวิธีที่ใช้บ่อยที่สุด:

อธิบาย
  • Method บอกเจตนา: GET อ่าน, POST สร้าง, PUT แก้, DELETE ลบ
  • :name คือ path parameter ไปอยู่ใน req.params.name ค่าเป็น string เสมอ ถ้าต้องการเลขใช้ Number() หรือ +
  • req.query คือค่าหลังเครื่องหมาย ? เป็น string เช่นกัน ใช้ ?? ใส่ค่าเริ่มต้นเมื่อไม่ส่งมา
  • res.json(obj) ส่ง JSON และตั้ง Content-Type ให้เอง, res.status(201) ตั้งรหัสสถานะ (ต่อกับ .json() ได้)
  • res.status(204).end() ตอบว่าสำเร็จแต่ไม่มีเนื้อหา ใช้กับการลบ
  • app.route('/book') รวมหลาย method ของ URL เดียวกันไว้ด้วยกัน

ทดสอบด้วย curl

ถ้าไม่อยากพิมพ์ curl ใช้ Postman หรือหน้า Swagger ตามหัวข้อ B13 ในส่วน B13 แทนได้

Middleware: ด่านตรวจที่เรียงกัน

Middleware คือฟังก์ชัน (req, res, next) ที่ทำงานก่อน route จะตอบ ใช้ทำงานที่ซ้ำกันทุก request เช่น บันทึก log, ตรวจล็อกอิน, อ่าน body เมื่อทำเสร็จต้องเรียก next() เพื่อส่งต่อ หรือตอบกลับเลยเพื่อหยุดตรงนั้น

อธิบาย
  • ลำดับสำคัญมาก: Express ไล่จากบนลงล่าง request หนึ่งตัวผ่านเฉพาะ middleware ที่อยู่เหนือ route ที่ตรง ตัวอย่างเช่น /public ไม่ผ่านตัวที่ 3 เพราะ route อยู่เหนือมัน
  • app.use(fn) ใส่ middleware ให้ทุก URL, app.use('/api', fn) ใส่เฉพาะ URL ที่ขึ้นต้นด้วย /api
  • ตัว 404 ท้ายสุดจับ request ที่ไม่ตรง route ใดเลย

middleware สำเร็จรูปที่ใช้บ่อย

express.static('public')เสิร์ฟไฟล์ในโฟลเดอร์ (รูป, CSS, HTML) ตรงๆมากับ Express

Router: แยกไฟล์ และ CRUD ครบชุด

เมื่อ route เริ่มเยอะ แยกเป็นไฟล์ด้วย Router() ตัวอย่างนี้ทำ CRUD ของ Todo โดยเก็บข้อมูลในตัวแปร (ยังไม่ใช้ฐานข้อมูล) เพื่อให้เห็นโครงก่อน ติดตั้ง cors เพิ่มก่อน:

อธิบาย
  • ไฟล์ todos.js เขียน router.get('/') แต่เมื่อ app.use('/todos', todoRoutes) จริงๆ URL คือ /todos นี่คือประโยชน์ของ Router: ไม่ต้องพิมพ์คำนำหน้าซ้ำ
  • รหัสสถานะที่เหมาะสม: 201 สร้างสำเร็จ, 204 ลบสำเร็จ, 400 ข้อมูลที่ส่งมาผิด, 404 ไม่พบ
  • return res.status(404)... ใส่ return เพื่อหยุดฟังก์ชันตรงนั้น ถ้าลืม โค้ดบรรทัดถัดไปจะรันต่อและพยายามตอบซ้ำจนเกิด error Cannot set headers after they are sent
  • เปรียบเทียบ PUT แบบนี้กับของจริง: เราแก้เฉพาะฟิลด์ที่ส่งมา (เหมือน PATCH) ซึ่งสะดวกกับฟอร์มแก้ไขทั่วไป

โครงโปรเจกต์ที่แนะนำเมื่อโตขึ้น

src/
├─ app.js                 ← ประกอบ middleware + route เข้าด้วยกัน
├─ routes/*.routes.js     ← จับคู่ URL กับ controller
├─ controllers/*.js       ← ตรรกะของแต่ละ endpoint (รับ req ตอบ res)
├─ middlewares/*.js       ← auth, upload, validate
└─ utils/*.js             ← ตัวช่วยเล็กๆ ที่ใช้ร่วมกัน

ตัวอย่างจริงของโครงนี้อยู่ที่ ขั้น B4-B6

จัดการ Error

Express มีที่จัดการ error ที่เดียว: middleware ที่มี 4 พารามิเตอร์ (err, req, res, next) วางท้ายสุด error จากทุกที่จะมารวมกันที่นี่ จึงไม่ต้องเขียน try/catch ซ้ำทุก route

อธิบาย
  • throw ใน function ธรรมดา Express จับให้เอง แต่ใน async function (Express 4) จับไม่ได้ promise ที่ล้มเหลวจะหลุดไป และตั้งแต่ Node 15 จะทำให้ทั้งเซิร์ฟเวอร์ปิดตัว จึงต้องห่อด้วย ah ที่เรียก .catch(next) ให้
  • httpError(404, '...') แนบ status ไปกับ error ตัวจัดการ error ท้ายสุดอ่านค่านี้ไปตั้งรหัสตอบกลับ ถ้าไม่มีใช้ 500
  • ถ้าเป็น error ที่เราไม่ได้คาดไว้ (500) ของจริงควรตอบข้อความกลางๆ และ log รายละเอียดไว้ ไม่ส่งรายละเอียดภายในให้ผู้ใช้เห็น
  • ใน Express 5 ไม่ต้องใช้ ah อีก (ดูหัวข้อ C11)

อัปโหลดไฟล์ด้วย multer

Express อ่านไฟล์ที่ส่งแบบ multipart/form-data ไม่ได้เอง ใช้ multer เป็น middleware คั่นหน้า route

อธิบาย
  • upload.single('photo'), .array(), .fields() เลือกตามจำนวนช่องไฟล์ ชื่อต้องตรงกับ name="" ของ input ฝั่งหน้าเว็บ ถ้าไม่ตรงจะได้ req.file เป็น undefined
  • diskStorage เก็บลงดิสก์ (ใช้กับไฟล์ที่ต้องเปิดดูทีหลัง) ส่วน multer.memoryStorage() เก็บใน RAM เป็น req.file.buffer เหมาะกับส่งต่อไปที่อื่น เช่น S3
  • ฟิลด์ข้อความที่มากับฟอร์มเดียวกันอยู่ใน req.body (เป็น string ทั้งหมด)
  • limits.fileSize กันไฟล์ใหญ่ และ fileFilter กรองชนิดไฟล์ แต่ mimetype มาจาก client จึงปลอมได้ ถ้าต้องการปลอดภัยจริงต้องตรวจเนื้อหาไฟล์เพิ่ม
  • ถ้าบันทึก path ลงฐานข้อมูล อย่าลืมลบไฟล์เมื่อลบ/แก้ข้อมูล และลบไฟล์ที่เพิ่งอัปโหลดเมื่อ request ล้มเหลว (ตัวอย่างเต็มอยู่ใน ขั้น B6)

ตัวแปรสภาพแวดล้อม (.env)

ค่าที่เปลี่ยนตามเครื่อง และค่าลับ (พอร์ต, รหัสผ่านฐานข้อมูล, secret ของ JWT) ไม่ควรเขียนในโค้ด ให้เก็บในไฟล์ .env แล้วอ่านผ่าน process.env

อธิบาย
  • --env-file=.env เป็นความสามารถในตัวของ Node 20.6 ขึ้นไป ไม่ต้องติดตั้ง dotenv
  • เพิ่ม .env ลง .gitignore เสมอ ห้ามอัปโหลดขึ้น GitHub แล้วทำไฟล์ .env.example ที่มีแต่ชื่อตัวแปร ไม่มีค่าลับ ไว้บอกเพื่อนร่วมทีม
  • ตอน deploy ให้ตั้งตัวแปรเหล่านี้ในหน้าตั้งค่าของผู้ให้บริการ ไม่ใช่อัปโหลดไฟล์ .env

ล็อกอินด้วย JWT

แนวคิด: ผู้ใช้ส่งอีเมลและรหัสผ่าน ถ้าถูก เซิร์ฟเวอร์ออก token (JWT) ให้ ต่อไปผู้ใช้แนบ token มากับทุก request เพื่อพิสูจน์ตัวตน

อธิบาย
  • ห้ามเก็บรหัสผ่านตรงๆ ใช้ bcrypt.hash แปลงเป็น hash ทางเดียว แล้วตอนล็อกอินใช้ bcrypt.compare เทียบ ต่อให้ฐานข้อมูลรั่ว ก็ไม่เห็นรหัสจริง
  • jwt.sign(payload, SECRET, { expiresIn }) สร้าง token ที่เซ็นด้วยความลับของเซิร์ฟเวอร์ ใครแก้ token ก็ตรวจพบ ใส่ข้อมูลลับใน payload ไม่ได้ เพราะใครก็ถอดอ่านได้ (แค่แก้ไม่ได้)
  • auth เป็น middleware ธรรมดา ใส่หน้า route ที่ต้องการป้องกัน: app.get('/me', auth, handler) ถ้าตรวจไม่ผ่านตอบ 401 แล้วหยุด
  • ฝั่งหน้าเว็บส่ง token ใน header: fetch(url, { headers: { Authorization: 'Bearer ' + token } })
  • ตัวอย่างนี้เป็นแบบย่อเพื่อเรียน ของจริงควรเพิ่ม rate limit กันเดารหัส และเก็บ token ให้ปลอดภัยฝั่งหน้าเว็บ

Routing: โฟลเดอร์ = URL

ใน App Router ชื่อโฟลเดอร์ใต้ app/ คือ URL และต้องมีไฟล์ชื่อ page.js ในโฟลเดอร์นั้นจึงจะเป็นหน้าที่เปิดได้ ไฟล์ที่มีชื่อพิเศษแต่ละตัวมีหน้าที่ของมัน:

ไฟล์หน้าที่
page.jsเนื้อหาของหน้า (ทำให้ URL นั้นเปิดได้)
layout.jsโครงที่ห่อหน้าลูกทุกหน้า ไม่โหลดใหม่ตอนเปลี่ยนหน้า (เมนู, footer)
loading.jsแสดงระหว่างรอข้อมูลของหน้า (D5)
error.jsแสดงเมื่อหน้ามี error (D5)
not-found.jsหน้า 404
route.jsAPI endpoint แทนที่จะเป็นหน้า (D7)
โฟลเดอร์URL ที่ได้ใช้เมื่อ
app/about/page.js/aboutหน้าธรรมดา
app/blog/[id]/page.js/blog/5, /blog/abcURL ที่มีค่าเปลี่ยนได้ (dynamic)
app/docs/[...slug]/page.js/docs/a, /docs/a/b/cรับหลายระดับ (catch-all)
app/(shop)/pricing/page.js/pricingวงเล็บ = จัดกลุ่มโฟลเดอร์ ไม่นับเป็น URL

เริ่มด้วยเลย์เอาต์ เมนู และหน้าธรรมดาต่างๆ:

อธิบาย
  • layout.js ต้องมี <html> และ <body> และต้องแสดง {children} (คือหน้าที่กำลังเปิดอยู่)
  • ใช้ <Link href="..."> ไม่ใช่ <a> เพื่อเปลี่ยนหน้าโดยไม่โหลดเว็บใหม่ทั้งหน้า และ Next โหลดหน้าถัดไปรอล่วงหน้าให้
  • usePathname() บอก path ปัจจุบัน ใช้ได้เฉพาะใน client component จึงแยก NavLinks เป็นไฟล์ที่มี 'use client' (อธิบายในหัวข้อ D3)
  • เปลี่ยนหน้าด้วยโค้ด: useRouter().push('/x') (ใน client component) หรือ redirect('/x') จาก next/navigation (ใน server)

Server Component vs Client Component

นี่คือแนวคิดที่สำคัญที่สุดของ App Router: component ทุกตัวเป็น Server Component โดยปริยาย รันบนเซิร์ฟเวอร์ ส่งแค่ HTML ไปให้เบราว์เซอร์ ถ้าต้องการให้ทำงานในเบราว์เซอร์ ใส่ 'use client' บรรทัดแรกของไฟล์

Server Component (ค่าเริ่มต้น)Client Component ('use client')
รันที่เซิร์ฟเวอร์เบราว์เซอร์ (และเรนเดอร์ HTML แรกบนเซิร์ฟเวอร์ด้วย)
ดึงข้อมูลasync + await fetch ตรงๆ ใน componentต้องใช้ useEffect หรือไลบรารี
ใช้ useState / useEffectไม่ได้ได้
event เช่น onClick, onChangeไม่ได้ได้
เข้าถึง window, localStorageไม่ได้ได้
เห็นตัวแปรลับ (process.env.SECRET)ได้ (ไม่ถูกส่งไปเบราว์เซอร์)ไม่ได้
ขนาด JS ที่ส่งไปเบราว์เซอร์ไม่มีมี

หลักการ: ใช้ server component เป็นหลัก แล้วแยกเฉพาะ "ส่วนเล็กๆ ที่ต้องโต้ตอบ" ออกเป็น client component ตัวอย่าง:

กฎที่พลาดบ่อย: server component import client component ได้ แต่ client component จะ import server component โดยตรงไม่ได้ (ส่งเป็น children แทนได้) และเมื่อไฟล์หนึ่งมี 'use client' ไฟล์ทั้งหมดที่มัน import ก็กลายเป็น client ด้วย

ดึงข้อมูลจาก API

ใน server component เขียน async แล้ว await fetch(...) ได้เลย ไม่ต้องใช้ useEffect หน้าเว็บที่ส่งไปมีข้อมูลครบตั้งแต่แรก ตัวอย่างนี้ดึงรายการจาก Todo API ของ Express (ส่วน C หัวข้อ C5):

อธิบาย
  • รัน Express ตัวอย่างหัวข้อ C5 ไว้ที่พอร์ต 3000 ก่อน (node todos-api/app.js) ถ้าไม่รัน หน้านี้จะ error
  • แคชของ fetch (Next 15): ค่าเริ่มต้นคือ ไม่แคช (Next 14 เคยแคชเป็นค่าเริ่มต้น) cache: 'no-store' ที่ใส่ไว้คือการระบุให้ชัดเจน
  • ถ้าข้อมูลไม่ค่อยเปลี่ยน ให้แคชแล้วรีเฟรชทุก 60 วินาที: fetch(url, { next: { revalidate: 60 } })
  • process.env.API_URL ไม่มี NEXT_PUBLIC_ นำหน้า จึงอ่านได้เฉพาะบนเซิร์ฟเวอร์ (ตั้งใน .env.local ดูหัวข้อ D9)
  • ถ้าต้องดึงข้อมูลหลังผู้ใช้กดปุ่ม หรือต้องอัปเดตหน้าโดยไม่โหลดใหม่ ใช้ client component + useEffect + fetch แบบที่ทำในส่วน B (ไฟล์ app/page.js ของโปรเจกต์ CRUD)

CSS Modules: ไฟล์ที่ลงท้าย .module.css ใช้ผ่าน import s from './x.module.css' แล้วเขียน className={s.item} Next เปลี่ยนชื่อคลาสให้ไม่ซ้ำกัน จึงไม่ชนกับหน้าอื่น

Dynamic route, loading, error, 404

อธิบาย
  • [id] ในชื่อโฟลเดอร์ทำให้ /blog/5 ส่งค่า 5 เข้า params.id ส่วน ?lang=en อยู่ใน searchParams
  • Next 15 เปลี่ยน: params และ searchParams เป็น Promise ต้องเขียน await params ถ้าลืมจะได้ค่า undefined หรือคำเตือนตอนพัฒนา
  • generateMetadata สร้าง <title> ตามข้อมูลของหน้า (ผลคือ "บทความ #5 | My Shop" จาก template ใน layout)
  • notFound() หยุดเรนเดอร์แล้วแสดง not-found.js พร้อมรหัส 404
  • loading.js ที่วางในโฟลเดอร์ todos/ แสดงทันทีระหว่างรอ await fetch ของหน้านั้น ผู้ใช้ไม่ต้องเจอหน้าขาว
  • error.js ดักข้อผิดพลาดของหน้านั้น (เช่น Express ปิดอยู่) ปุ่ม reset() ลองเรนเดอร์ใหม่ ตอนใช้งานจริง (production) Next ซ่อนข้อความ error ภายใน error.message จะเป็นข้อความทั่วไป

ฟอร์มและ Server Actions

Server Action คือฟังก์ชันที่รันบนเซิร์ฟเวอร์ แต่เรียกจากฟอร์มในหน้าเว็บได้ตรงๆ โดยไม่ต้องเขียน API และ fetch เอง ใส่ 'use server' บรรทัดแรกของไฟล์

อธิบาย
  • <form action={fn}> ส่งข้อมูลฟอร์มเข้า fn(formData) บนเซิร์ฟเวอร์ ใช้ formData.get('ชื่อ input') อ่านค่า
  • ฟอร์มแบบนี้ ทำงานได้แม้ JavaScript ยังโหลดไม่เสร็จ (ส่งเป็นฟอร์มธรรมดา) พอโหลดเสร็จก็ส่งแบบไม่รีเฟรชหน้า
  • useActionState (React 19) ให้ได้ state (ผลที่ action คืนมา เช่น ข้อความ error), formAction (ส่งให้ action) และ pending (กำลังส่งอยู่ ใช้ปิดปุ่ม) ต้องอยู่ใน client component
  • revalidatePath('/todos') ล้างแคชของหน้านั้นเพื่อให้เห็นข้อมูลใหม่ และ redirect() พาไปหน้าอื่นหลังสำเร็จ (ต้องเรียกท้ายสุด)
  • deleteTodo.bind(null, t.id) คือการฝาก id ให้ฟังก์ชันล่วงหน้า เพื่อให้ปุ่มลบแต่ละรายการรู้ว่าต้องลบอะไร
  • Server action คือ endpoint สาธารณะ ใครก็ส่งข้อมูลมาได้ ต้องตรวจข้อมูลและสิทธิ์ในฟังก์ชันเสมอ เหมือนเขียน API

Route Handler: เขียน API ใน Next

สร้างไฟล์ route.js แล้ว export ฟังก์ชันที่ชื่อตรงกับ HTTP method มันใช้ Request/Response มาตรฐานของเว็บ ไม่ใช่ req/res แบบ Express

อธิบาย
  • ไฟล์นี้ตอบที่ /api/hello ตามโฟลเดอร์ ใช้ [id] ในชื่อโฟลเดอร์ได้เหมือนหน้าธรรมดา
  • Response.json(data, { status }) คือคู่ของ res.status().json()
  • ใน Next 15 ฟังก์ชัน GET ไม่ถูกแคชเป็นค่าเริ่มต้น
  • เมื่อไรควรใช้: งานเล็กๆ เช่น รับ webhook หรือซ่อน API key ถ้าเป็นหลังบ้านใหญ่ที่มีฐานข้อมูลและอัปโหลดไฟล์ ใช้ Express แยกต่างหากตามที่คอร์สนี้ทำ

รูปภาพด้วย next/image

<Image> ย่อขนาดรูปให้เหมาะกับหน้าจอและโหลดแบบ lazy ให้อัตโนมัติ ถ้ารูปมาจากเซิร์ฟเวอร์อื่น (เช่น Express ที่เก็บรูปที่อัปโหลด) ต้องอนุญาตโดเมนนั้นก่อน ใน next.config.mjs

อธิบาย
  • width / height บังคับใส่สำหรับรูปจากภายนอก เพื่อกันหน้ากระตุกตอนรูปโหลด
  • ถ้าไม่ตั้ง remotePatterns ตอนรัน npm run dev จะขึ้น error (หน้าเว็บตอบ 500): hostname "localhost" is not configured under images in your next.config.js
  • แก้ next.config.mjs แล้วต้องรีสตาร์ท npm run dev
  • ตอน deploy จริง เปลี่ยน hostname เป็นโดเมนของ API ของคุณ และเปลี่ยน protocol เป็น https
  • ในโปรเจกต์ CRUD ของคอร์สนี้ใช้ <img> ธรรมดา เพราะง่ายกว่าและไม่ต้องตั้งค่า เหมาะกับงานเรียน

  • Next 16 เปลี่ยนชื่อไฟล์นี้เป็น proxy.js (ดูหัวข้อ D13)

F. นำ HTML/CSS ที่โจทย์ให้มาใช้

กรณีโจทย์ให้ไฟล์ HTML และ CSS มาแล้ว และไม่บังคับโครงสร้าง ใช้ Express หรือ NestJS ทำหลังบ้าน ส่วนนี้สอนทุกวิธีที่ใช้ได้ พร้อมโค้ดที่ผมรันทดสอบแล้ว (Express 4, NestJS 12, Node 24)

ทำส่วน A เสร็จแล้วใช่ไหม? ข้ามไปที่ F3 ได้เลย ใช้ Express เดิมเสิร์ฟ HTML/CSS ของอาจารย์ได้ ไม่ต้องลง Next.js เพิ่ม ถ้ากำลังเตรียมสอบ ให้ดูส่วน ห้องสอบ แทน (สั้นกว่า)

เลือกวิธีให้เหมาะกับโจทย์

ก่อนลงมือ ให้ดูว่า HTML ที่ได้มามีส่วนที่ต้องเปลี่ยนตามข้อมูลไหม (เช่น รายการสินค้า ตารางสมาชิก) และโจทย์ต้องการอะไรบ้าง (อ่านอย่างเดียว หรือ เพิ่ม/แก้/ลบ/อัปโหลด) แล้วเลือกจากตาราง:

วิธีหน้าเว็บทำงานยังไงข้อดีข้อเสีย
1 Express เสิร์ฟไฟล์ + JS เรียก APIExpress ส่ง HTML/CSS ตรงๆ แล้ว JavaScript ในหน้าเรียก /api/... มาสร้างเนื้อหาแก้ HTML เดิมน้อยที่สุด ไม่ต้องเรียนเครื่องมือเพิ่มต้องเขียน JS ฝั่งหน้าเว็บเอง
2 Express + EJSExpress เอาข้อมูลมาเติมใน HTML (template) แล้วส่งหน้าที่สมบูรณ์ไปเลยไม่ต้องเขียน JS ฝั่งหน้า ฟอร์ม HTML ธรรมดาใช้ได้เลย หน้าที่ส่งไปมีเนื้อหาครบกดเพิ่ม/ลบแล้วหน้าโหลดใหม่ทั้งหน้า
3 NestJS เสิร์ฟไฟล์ + REST APIเหมือนวิธี 1 แต่ใช้ NestJS เป็นหลังบ้าน (TypeScript) สร้างหน้า Swagger ให้อัตโนมัติโครงสร้างเป็นระเบียบ มี validation และ Swagger ในตัวเรียนรู้เพิ่ม (decorator, module, TypeScript)
4 NestJS + EJSเหมือนวิธี 2 แต่ใช้ NestJSใช้ไฟล์ views/ ชุดเดียวกับวิธี 2 ได้เหมือนวิธี 3 และหน้าโหลดใหม่ทั้งหน้า
5 แปลงเป็น Next.jsย้าย HTML เป็น JSX แล้วดึงข้อมูลจาก APIเหมาะกับหน้าเว็บที่โต้ตอบเยอะต้องแปลง HTML ทุกหน้า และเรียน React
คำแนะนำ: ถ้าโจทย์ให้ HTML สำเร็จรูปและเน้นหลังบ้าน ให้เริ่มจาก วิธี 2 (Express + EJS) หรือ วิธี 1 เพราะแก้ HTML น้อย ใช้ NestJS เมื่อโจทย์ระบุหรืออยากได้โครงสร้างแบบมืออาชีพ และใช้ Next.js เมื่อโจทย์ต้องการหน้าเว็บแบบ React ก่อนส่งงาน ให้เช็กโจทย์ว่ามีข้อกำหนดเรื่องเครื่องมือที่ต้องใช้หรือไม่

เตรียม HTML/CSS ที่ได้มา

ตัวอย่างในส่วนนี้สมมติว่าโจทย์ให้เว็บร้านค้ามา 2 หน้า พร้อมไฟล์ CSS: index.html (หน้าร้าน) กับ admin.html (จัดการสินค้า) ข้อมูลสินค้าถูกเขียนตายตัวไว้ใน HTML ทั้งหมด คุณจะเจอแบบนี้กับไฟล์ของจริง แค่หน้าตาต่างกัน

สิ่งที่ต้องทำกับไฟล์ที่ได้มาเสมอ (ทุกวิธี)

  1. ย้ายไฟล์ที่เบราว์เซอร์ต้องโหลดไปไว้ใน public/ เช่น public/css/style.css, public/img/logo.png ตั้งค่าให้ Express/Nest เสิร์ฟโฟลเดอร์นี้ที่ราก (/) ดังนั้นไฟล์ public/css/style.css เปิดได้ที่ /css/style.css (ไม่มีคำว่า public ใน URL)
  2. แก้ path ใน HTML ให้ขึ้นต้นด้วย / จาก href="css/style.css" เป็น href="/css/style.css" และ src="img/pen.png" เป็น src="/img/pen.png" ถ้าไม่แก้ path แบบ relative จะใช้ได้เฉพาะหน้า / พอไปหน้าลึกอย่าง /admin/products เบราว์เซอร์จะหา CSS ผิดที่ และหน้าจะไม่มีสไตล์
  3. เช็ก path ใน CSS ถ้ามี url('../img/bg.jpg') ให้แน่ใจว่ายังชี้ถูกที่ หรือเปลี่ยนเป็น url('/img/bg.jpg')
  4. ลิงก์ระหว่างหน้า จาก href="index.html" เป็น href="/" และหน้าอื่นเป็นเส้นทางที่เราสร้าง เช่น /admin
  5. หาส่วนที่ซ้ำและส่วนที่ต้องเปลี่ยนตามข้อมูล ในตัวอย่างคือการ์ดสินค้า 3 อัน ส่วนที่เป็นเมนูกับ footer ซ้ำทุกหน้า ทั้งสองอย่างนี้คือสิ่งที่แต่ละวิธีจัดการต่างกัน

ทำต่อจากส่วน A: ใช้ HTML/CSS กับ API เดิม

ไม่ต้องติดตั้ง Next.js เพิ่ม Express ที่สร้างจากส่วน A เสิร์ฟไฟล์ HTML/CSS ของอาจารย์ได้เองจากพอร์ต 3000 (พอร์ตเดียวกับ API) หน้าเว็บเรียก /api/products และ /api/categories ที่มีอยู่แล้ว ข้อมูลจึงมาจากฐานข้อมูล Prisma จริง และ /docs (Swagger) ใช้ได้เหมือนเดิม Next.js (พอร์ต 3001) เป็นทางเลือกอื่น ไม่ใช่สิ่งที่ต้องมีเพิ่ม

หัวข้อนี้ใช้ตัวอย่างจากหัวข้อ F2 (index.html, admin.html, style.css) ทำให้ใช้งานจริงทีละขั้น

วิธี 1: Express เสิร์ฟไฟล์ + JS เรียก API

แนวคิด: HTML เกือบเหมือนเดิม แต่การ์ด 3 อันที่เขียนตายตัวถูกแทนด้วย <main id="list"> ว่างๆ แล้วให้ JavaScript ดึงข้อมูลจาก API มาสร้างการ์ดให้

1) หลังบ้าน

2) HTML: เอาการ์ดตายตัวออก ใส่ที่ว่างให้ JS

3) JavaScript ของหน้า

อธิบาย
  • express.static('public') ทำให้ทุกไฟล์ใน public/ เปิดได้ตาม path ถ้ามี public/index.html เมื่อเปิด / จะได้ไฟล์นี้เอง
  • หน้าเว็บกับ API อยู่ที่ เซิร์ฟเวอร์เดียวกัน (พอร์ตเดียว) fetch('/api/products') ใช้ path สั้นๆ ได้ และไม่เจอปัญหา CORS
  • การ์ดที่ JS สร้างใช้ class="card" เหมือน HTML เดิม CSS ที่โจทย์ให้จึงทำงานโดยไม่ต้องแก้
  • ใช้ textContent แทน innerHTML เสมอเวลาใส่ข้อมูลที่ผู้ใช้กรอก ไม่เช่นนั้นคนพิมพ์ <script> เข้ามาแล้วโค้ดนั้นจะรันในหน้าของผู้อื่นได้ (XSS)
  • ในฟอร์มห้ามอ่านค่าด้วย form.name เพราะ form.name คือชื่อของฟอร์มเอง ให้ใช้ new FormData(form).get('name')

รันด้วย node server-static.js แล้วเปิด http://localhost:3000 ถ้าจะเก็บข้อมูลลงฐานข้อมูลจริง ให้เปลี่ยนตัวแปร products เป็น Prisma ตามส่วน B ส่วนการอัปโหลดรูปทำตามหัวข้อ C7 และฝั่งหน้าเว็บส่งด้วย FormData (ดู Cheatsheet)

วิธี 2: Express + EJS (เติมข้อมูลลง HTML ที่ฝั่งเซิร์ฟเวอร์)

EJS คือตัวช่วยเติมข้อมูลลงใน HTML (template engine) ไฟล์ที่ได้ยังเป็น HTML เกือบเหมือนเดิม แต่แทรกคำสั่งได้ด้วยเครื่องหมาย 3 แบบ:

เขียนความหมาย
<%= ตัวแปร %>แสดงค่า และแปลงอักขระพิเศษให้ปลอดภัย (ใช้เป็นหลัก)
<%- ... %>แสดงค่าแบบดิบ ไม่แปลง ใช้กับ include เท่านั้น ห้ามใช้กับข้อมูลที่ผู้ใช้กรอก
<% คำสั่ง JS %>รันโค้ด ไม่แสดงอะไร (ใช้ if, forEach)

1) แยกส่วนที่ซ้ำ (header / footer) เป็น partial

2) หน้าแรก: การ์ดตายตัวกลายเป็นลูป

3) หน้าจัดการสินค้า (ฟอร์ม HTML ธรรมดา)

4) เซิร์ฟเวอร์

อธิบาย
  • app.set('view engine', 'ejs') บอก Express ว่าไฟล์หน้าเป็น .ejs และอยู่ในโฟลเดอร์ views (ที่โฟลเดอร์ที่รัน) จากนั้น res.render('index', { products }) จะเปิด views/index.ejs และส่งตัวแปร products เข้าไป
  • การ์ดตายตัว 3 อันกลายเป็น products.forEach โครง <article class="card"> ยังเหมือนเดิม จึงใช้ CSS เดิมได้ทันที
  • include('partials/header') ดึงส่วนที่ซ้ำมาใส่ทุกหน้า แก้เมนูครั้งเดียวเปลี่ยนทุกหน้า ใช้ <%- %> เพราะต้องการ HTML ดิบของ partial
  • ฟอร์ม HTML ส่งได้แค่ GET และ POST จึงใช้ POST /admin/products/:id/delete แทน DELETE (ถ้าต้องการให้เป็น DELETE จริง ต้องใช้ JavaScript ตามวิธี 1)
  • Post/Redirect/Get: หลังรับฟอร์ม POST ให้ redirect ไปหน้า GET เสมอ ถ้าตอบหน้าเว็บตรงๆ แล้วผู้ใช้กด refresh เบราว์เซอร์จะถามว่าจะส่งฟอร์มซ้ำ ทำให้เพิ่มสินค้าซ้ำสองชิ้น
  • อย่าให้มี public/index.html ค้างอยู่ เพราะ express.static('public') อยู่ก่อน route และจะตอบไฟล์นั้นที่ / แทนหน้าที่ render จาก EJS (ผมเจอปัญหานี้ตอนทดสอบ ถ้าย้าย HTML ที่ได้มาเข้า views/ แล้ว ให้ลบต้นฉบับใน public/ ทิ้ง)
  • enctype="multipart/form-data" ในฟอร์มจำเป็นเมื่อมี <input type="file"> ถ้าลืม ไฟล์จะไม่ถูกส่ง
  • <%= p.name %> แปลงอักขระพิเศษให้เอง ถ้ามีคนตั้งชื่อสินค้าว่า <script>... หน้าจะแสดงเป็นข้อความ ไม่ใช่รันโค้ด

เปิด http://localhost:3000 และ /admin เพื่อทดสอบ ถ้าจะใช้ฐานข้อมูลจริง ให้เปลี่ยน products เป็น await prisma.product.findMany() ตามส่วน B (ห่อ route ด้วย ah ตามหัวข้อ C6)

วิธี 3: NestJS เสิร์ฟไฟล์ + REST API + Swagger

NestJS คือเฟรมเวิร์กหลังบ้านที่วางบน Express เขียนด้วย TypeScript แบ่งงานเป็นชั้นชัดเจน: Controller (รับ request) · Service (ตรรกะ/ข้อมูล) · Module (รวมเข้าด้วยกัน) และมี decorator (เครื่องหมาย @) บอกหน้าที่ เช่น @Get(), @Post()

1) สร้างโปรเจกต์

อธิบาย
  • ผมสร้างโปรเจกต์ด้วย CLI เวอร์ชันล่าสุด (NestJS 12) แล้วตรวจโครงสร้างจริง: เป็น ES Module ("type": "module") และ TypeScript เข้มงวด
  • ข้อสำคัญของ NestJS 12: เวลา import ไฟล์ของเราเอง ต้องเติม .js ท้ายชื่อ เช่น from './products.service.js' (แม้ไฟล์จริงเป็น .ts) ถ้าลืมจะ build ไม่ผ่าน
  • ไฟล์ตัวอย่างที่ CLI สร้างให้ (app.controller, app.service) เราไม่ใช้ จึงลบทิ้ง รวมถึงโฟลเดอร์ test ที่อ้างถึงไฟล์เหล่านั้น
  • @types/multer ใช้เฉพาะวิธี 4 ตอนอัปโหลดไฟล์ (ให้ TypeScript รู้จักชนิด Express.Multer.File)

คัดลอก public/css/style.css จากหัวข้อ F2 ไว้ในโปรเจกต์นี้ และใช้ public/index.html กับ public/app.js ชุดเดียวกับวิธี 1 ได้ทันที เพราะ API มีรูปแบบเดียวกัน (/api/products)

2) Service: เก็บข้อมูลและตรรกะ

3) Controller: REST API + DTO ตรวจข้อมูล

4) Module และ main.ts

อธิบาย
  • ลำดับการทำงานเหมือน Express: request → ผ่านตัวตรวจ (ValidationPipe) → controller → ตอบกลับ เพียงแต่ Nest ให้เขียนเป็นคลาสและ decorator
  • process.cwd() คือโฟลเดอร์ที่สั่งรัน ต้องรัน npm run start ที่รากโปรเจกต์ (ที่มีโฟลเดอร์ public)
  • ValidationPipe + DTO: ส่งข้อมูลผิด (เช่น ไม่มี name) Nest ตอบ 400 พร้อมรายการข้อผิดพลาดให้เอง ไม่ต้องเขียน if ตรวจ whitelist: true ตัดฟิลด์ที่ไม่ได้ประกาศใน DTO ทิ้ง · transform: true ให้ @Transform ทำงาน (ตัดช่องว่างหน้าหลังของชื่อ ไม่เช่นนั้นชื่อที่เป็นช่องว่างล้วน " " จะผ่าน @MinLength(1))
  • Swagger: Nest อ่าน decorator (@ApiTags, @ApiProperty, @Get ...) แล้วสร้างหน้า Swagger ที่ /docs ให้เอง ไม่ต้องเขียน openapi.yaml ด้วยมือเหมือนใน Express (ส่วน B13) ตอบโจทย์ที่ให้ส่ง Swagger ได้ตรงๆ
  • ถ้าอาจารย์ให้ไฟล์สเปกมาก่อน ให้ใช้เป็นแบบ ตั้งชื่อ route, DTO และรหัสสถานะให้ตรง แล้วเทียบกับหน้า /docs ที่ Nest สร้าง

เปิด http://localhost:3000 (หน้าร้านจาก public/index.html) และ /docs (Swagger)

วิธี 4: NestJS + EJS (เติมข้อมูลลง HTML ที่ฝั่งเซิร์ฟเวอร์)

ใช้ไฟล์ views/partials/header.ejs, footer.ejs, index.ejs, admin.ejs ชุดเดียวกับวิธี 2 ทุกไฟล์ (หัวข้อ F5) คัดลอกมาไว้ใน views/ ของโปรเจกต์ Nest ได้เลย และลบ public/index.html ทิ้ง ไม่เช่นนั้นไฟล์นั้นจะถูกเสิร์ฟที่ / ก่อน controller (main.ts ที่ตั้งค่าไว้ในวิธี 3 รองรับ view อยู่แล้ว)

อธิบาย
  • @Render('index') คือคู่ของ res.render('index', data) ค่าที่ method return จะเป็นข้อมูลที่ส่งเข้า template
  • @Redirect('/admin') คือคู่ของ res.redirect ถ้าต้องการปลายทางอื่นในบางกรณี ให้ return { url: '...' }
  • @UseInterceptors(FileInterceptor('image', ...)) คือคู่ของ upload.single('image') ไฟล์จะมาที่พารามิเตอร์ @UploadedFile() ชื่อ 'image' ต้องตรงกับ name="image" ใน HTML
  • ฟอร์ม HTML ส่งเป็น application/x-www-form-urlencoded หรือ multipart ซึ่ง Nest อ่านเข้า @Body() ให้เอง (ไม่ต้องเรียก express.urlencoded)
  • ประกาศชนิดของ body เป็น { name?: string; price?: string } (ไม่ใช่คลาส DTO) เพราะค่าจากฟอร์มเป็น string ทั้งหมด ตรวจเองเหมือนใน Express

วิธี 5: แปลง HTML เป็น Next.js

ถ้าโจทย์ต้องการ Next.js หรืออยากให้หน้าเว็บเป็น React ให้ย้าย HTML เป็น JSX ดังนี้ (ภาพรวมของ Next อยู่ที่ส่วน D)

  1. คัดลอก CSS ทั้งไฟล์ไปไว้ที่ app/globals.css โดยไม่แก้ แล้ว import ใน layout.js
  2. ย้ายรูป/ฟอนต์ไป public/ และใช้ path ขึ้นต้นด้วย / เช่น /img/logo.png

ลำดับการทำงานจริงเมื่อได้ HTML/CSS มา

  1. เปิดไฟล์ HTML ดูว่ามีกี่หน้า หน้าไหนมีส่วนที่ซ้ำหลายอัน (รายการ, ตาราง) และหน้าไหนมีฟอร์ม
  2. จัดโฟลเดอร์ public/ แล้วแก้ path ให้ขึ้นต้นด้วย / (หัวข้อ F2) เปิดผ่านเซิร์ฟเวอร์ให้เห็นหน้าเหมือนต้นฉบับก่อน ยังไม่ต้องต่อข้อมูล
  3. ออกแบบตารางฐานข้อมูล (Prisma) ให้ตรงกับข้อมูลที่หน้าเว็บแสดง และสร้าง API/route ตามส่วน B
  4. เปลี่ยนส่วนที่ซ้ำเป็นลูปวนจากข้อมูล (วิธี 1: map ใน JS · วิธี 2 และ 4: forEach ใน EJS · วิธี 5: map ใน JSX) โดยเก็บ class เดิมไว้ทุกตัว
  5. เปลี่ยนฟอร์มให้ส่งไปหา route ที่สร้าง (วิธี 1 ใช้ fetch · วิธี 2 และ 4 ใช้ method="post") ถ้ามีอัปโหลดไฟล์ ใส่ enctype="multipart/form-data"
  6. เพิ่มหน้า error/ข้อความเมื่อกรอกผิด แล้วทดสอบเพิ่ม แก้ ลบ ให้ครบ
  7. เปิดหน้า Swagger /docs (Nest สร้างให้เอง · Express ใช้ส่วน B13) เพื่อส่งงาน
